# Package the standalone labs

`dist/*.html` is the **deliverable**: a single file per lab, double-clicked,
works offline, no server. It is generated by concatenation, not by a
bundler, and it is committed to the repository.

## 1. Rebuild

```powershell
node scripts/build-standalone.mjs
```

Produces one file per lab in `dist/`. The script fails loudly if a module
still contains an ESM import it cannot strip.

## 2. Check the drift

```powershell
git status --porcelain -- dist/
```

Anything listed means `dist/` no longer matches the sources. Rebuild, then
commit the result. CI fails on this drift.

## 3. Verify the four labs still work

```powershell
node tests/run-tests.mjs
node mcp-server/smoke-test.mjs
```

The tests boot every lab **headlessly** and simulate 600 frames, checking
that every measure stays finite. The smoke test drives every MCP tool.

## 4. What the standalone file contains

| Part | Source |
|---|---|
| styles | `core/styles.css` |
| core | `core/catalog.js`, `validate.js`, `time.js`, `controls.js`, `strings.js`, `headless.js`, `instruments.js`, `notebook.js`, `ghost.js`, `shell.js` |
| engine | the pack of the lab (`engines/<pack>/**`) |
| vendor | `app-ponts/vendor/three.min.js` for the 3D labs, raw |
| wiring | `app-<name>/lab.js` or `game.js` |
| config | `app-<name>/config.json`, inlined as an object |

## 5. Adding a lab to the distribution

Two places list the labs: `scripts/build-standalone.mjs` (the `labs` array)
and `index.html` (the portal cards). A new lab missing from either will not
be shipped or not be reachable.

## 6. Manual check

Open `dist/labkit-<name>.html` by double-clicking it. If a boot hint
appears instead of the lab, the page is trying to fetch something it should
have inlined.

## Rules

- Never hand-edit a file in `dist/`: it is regenerated.
- Rebuild in the same commit as the source change that caused the drift.
